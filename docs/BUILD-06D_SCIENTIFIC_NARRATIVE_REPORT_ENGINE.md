# BUILD-06D — Scientific Narrative / Report Engine

## Status
SCIENTIFIC NARRATIVE / REPORT CONTRACT LOCKED

## Purpose
BUILD-06D converts certified evidence, relationships, uncertainty, event reconstruction, future pathways, intervention tests and decision outputs into reproducible scientific narratives and report products. It is a **controlled evidence-to-text layer**, not a generative storytelling engine.

## 1. Core chain

```text
CERTIFIED EVIDENCE
      ↓
EVIDENCE–CLAIM MATRIX
      ↓
RELATIONSHIP + UNCERTAINTY REGISTRY
      ↓
NARRATIVE PLAN
      ↓
CLAIM-LEVEL PROVENANCE
      ↓
SCIENTIFIC TEXT / TABLE / FIGURE SPECIFICATION
      ↓
QA + CLAIM STRENGTH AUDIT
      ↓
REPRODUCIBLE REPORT
```

## 2. Narrative contract

Every substantive statement generated by the engine must map to one or more registered claims/evidence objects or be explicitly labelled as:

```text
METHOD
DEFINITION
ASSUMPTION
INTERPRETATION
LIMITATION
RECOMMENDATION
```

Unregistered factual claims are prohibited.


## 6. Claim strength gate

Language is constrained by evidence status:

```text
Observed
Measured
Estimated
Associated with
Consistent with
Suggests
Supports the hypothesis that
Modelled
Projected under
Scenario-dependent
Causal effect
```

The engine must not automatically escalate weaker evidence into stronger language.

## 7. Forbidden escalation

Prevent transformations such as:

```text
associated with → causes
suggests → demonstrates
modelled → observed
projected → forecast
scenario-consistent → certain
high support → proven
possible → likely
likely → inevitable
```

Unless an explicit evidence rule justifies the change.

## 8. Narrative planning

Before text generation, create a narrative plan:

```text
research question
argument structure
claims required
supporting evidence
counterevidence
uncertainty
logical dependencies
section destination
```

This prevents prose generation from inventing the analytical structure.

## 9. Scientific argument chain

Preferred structure:

```text
QUESTION
  ↓
EVIDENCE
  ↓
FINDING
  ↓
RELATIONSHIP / MECHANISM
  ↓
UNCERTAINTY
  ↓
INTERPRETATION
  ↓
IMPLICATION
```

Interpretation must remain distinguishable from observation.

## 10. Event reconstruction narrative

For reconstructed events:

```text
Event identity
 ↓
Chronology
 ↓
Spatial footprint
 ↓
Hazard characteristics
 ↓
Exposure
 ↓
Vulnerability
 ↓
Observed impacts
 ↓
Response
 ↓
Recovery
 ↓
Evidence gaps
 ↓
Reconstruction confidence
```

Conflicting historical evidence must be visible.

## 11. Cross-dimensional narrative

Relationships from BUILD-06B must be expressed with explicit status:

```text
observed association
spatial association
temporal association
mechanistic relationship
modelled dependency
causal evidence
```

The narrative cannot silently upgrade an association to causality.

## 12. Uncertainty narrative

BUILD-06C outputs must be incorporated into interpretation.

For important claims state, where relevant:

```text
what is uncertain
why it is uncertain
whether it is quantified
dominant uncertainty driver
whether the conclusion is sensitivity-dependent
confidence status
```

## 13. Scenario narrative

Scenario outputs must use conditional language:

```text
Under Scenario A...
If condition X holds...
Across the tested scenarios...
Under the declared assumptions...
```

A scenario is not written as a prediction unless it qualifies as one under the registered forecast framework.

## 14. Intervention narrative

Separate:

```text
technical/modelled effectiveness
implementation-adjusted effectiveness
observed effectiveness
residual risk
trade-offs
uncertainty
```

Do not report modelled intervention effects as observed programme outcomes.

## 15. Decision narrative

Decision results must distinguish:

```text
empirical evidence
model result
decision rule
normative preference
constraint
recommendation
```

The engine may explain why an option is robust under a declared rule but must not represent a value judgement as an empirical fact.

## 16. Tables

Generated tables must have:

```text
clear title
units
scope
source/provenance
uncertainty where relevant
footnotes
definitions
```

Derived values must be distinguishable from source values.

## 17. Figure specification

Every figure should declare:

```text
figure_id
type
data refs
spatial/temporal scope
variables
units
classification
uncertainty representation
caption
source
processing
```

Figures must not visually imply greater precision than the evidence supports.

## 18. Map narrative safeguard

Maps must state, where relevant:

```text
reference date
spatial unit
projection/CRS where material
classification method
data source
resolution
uncertainty / caveat
```

A map pattern is not automatically interpreted as causal geography.

## 19. Statistical reporting

Where applicable report:

```text
sample size
estimate
effect size
uncertainty interval
model specification
fit/performance
relevant assumptions
```

Do not report p-values as the sole evidence of substantive importance.

## 20. Reproducible methods narrative

Methods text must be generated from registered workflow metadata:

```text
input data
cleaning
transformations
sampling
models
parameters
software
versions
random seeds where applicable
validation
```

No undocumented analytical step may appear as if it were performed.

## 21. Reference integrity

The engine may cite only registered sources.

It must not:

```text
invent references
invent DOI
invent page number
invent author
invent publication date
```

Reference metadata should be validated before final report status.

## 22. Quote safeguard

If direct quotations are included, preserve exact source text and provenance. Automated paraphrase is preferred for synthesis unless quotation is analytically necessary.

## 23. Discussion engine

Discussion should distinguish:

```text
What was observed?
What relationship was identified?
What mechanism is plausible?
What remains uncertain?
How does it compare with prior evidence?
What alternative explanations remain?
What does the result imply?
What does it NOT establish?
```

## 24. Literature comparison

External literature may be incorporated only through registered evidence objects.

Comparisons must account for:

```text
study context
population
scale
time period
methods
definitions
measurement
```

Similarity of topic alone is insufficient for direct comparison.

## 25. Contradictory evidence reporting

If credible evidence conflicts:

```text
present conflict
identify plausible reasons
state unresolved status
avoid selective citation
```

The engine must not suppress inconvenient findings to create narrative coherence.

## 26. Limitation generator

Limitations should be linked to actual registered constraints:

```text
data coverage
measurement
sampling
scale
time
model
scenario
causal identification
implementation
external validity
```

Generic boilerplate limitations are not sufficient for research-ready status.

## 27. External validity

Every major conclusion should retain scope:

```text
study area
population
period
hazard/context
model domain
scenario domain
```

Local evidence must not be automatically generalized to all Himalayan systems.

## 28. Recommendation gate

Recommendations must distinguish:

```text
Evidence-supported implication
Decision-analytic recommendation
Normative recommendation
Research priority
Monitoring recommendation
```

Recommendations must state the basis and relevant uncertainty.

## 29. Abstract generator

The abstract should be assembled from certified components:

```text
Context/problem
Objective
Methods
Key results
Uncertainty/limitations
Conclusion
```

No new result may first appear in the abstract.

## 30. Executive summary safeguard

Executive summaries may simplify language but cannot remove material uncertainty, major caveats or contradictory evidence.

## 31. Conclusion gate

Conclusions may contain only claims supported by the integrated evidence graph.

The engine must check:

```text
Does conclusion exist in evidence graph?
Is scope preserved?
Is uncertainty preserved?
Is causal language justified?
Are scenario conditions retained?
```

## 33. Change impact

If upstream evidence changes:

```text
Evidence change
   ↓
Claim status change
   ↓
Narrative section stale
   ↓
Report invalidation
   ↓
Regenerate / re-audit
```

Material changes cannot be patched manually without updating provenance.

## 34. Human review gates

Required review before `RESEARCH_READY`:

```text
scientific claim review
method review
uncertainty review
citation/reference review
figure/table review
language/certainty review
```

Human review is mandatory for final scientific interpretation.

## 37. Stop conditions

Block or downgrade when:

```text
claim has no evidence lineage
citation is unregistered
causal language unsupported
projection written as observation
scenario written as certainty

scope generalized beyond evidence

method step undocumented
reference metadata unverified
upstream dependency stale
recommendation presented as empirical fact
human review incomplete
```

## 39. Acceptance criteria

BUILD-06D is accepted when:

- every substantive factual claim is traceable to registered evidence;
- claim classes and certainty language remain aligned;
- causal language is gated;
- observations, models, projections, forecasts and scenarios remain distinct;
- uncertainty and material caveats survive summarization;
- contradictory evidence cannot be silently removed;
- tables, figures and maps retain provenance and appropriate metadata;
- methods text reflects only registered analytical steps;
- references cannot be fabricated by the narrative engine;
- recommendations remain distinguishable from empirical findings;
- external-validity scope is preserved;
- report versions inherit upstream dependency versions;
- material upstream changes trigger report invalidation;
- final research-ready status requires human scientific review;
- the complete report is reproducible from the declared evidence graph and workflow metadata.

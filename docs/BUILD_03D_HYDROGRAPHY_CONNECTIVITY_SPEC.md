# BUILD-03D — Hydrography, River–Tributary Network & Downstream Connectivity

## Objective
Build a topology-aware hydrography graph that connects validated glacier/lake source features to downstream stream reaches, tributaries, rivers and exposed places.

## Core principle
Hydrographic connectivity is not equivalent to hazard. A connected downstream settlement is a candidate exposure location, not an automatically affected location.

## Data flow

`hydrography source → ingestion → geometry/topology QA → reach segmentation → direction validation → network graph → glacier/lake linkage → downstream traversal → exposure linkage`

## Network entities

- waterbody
- outlet
- stream reach
- tributary
- river reach
- confluence
- basin/sub-basin
- glacier source
- glacial lake source

## Reach identity

Each reach keeps its original source ID and receives a stable HG-SCRIS reach identifier. Source IDs are never overwritten.

## Required reach attributes

- reach_id
- source_dataset
- source_id
- geometry
- reach_type
- stream order where available
- upstream_id
- downstream_id
- basin_id
- glacier/lake source linkage where established
- length
- upstream elevation
- downstream elevation
- longitudinal gradient
- connectivity status
- QA status
- lineage

## Directionality

Every routed reach must have an explicit upstream-to-downstream direction. Direction cannot be inferred solely from line vertex order without QA.

## Topology QA

Check:

1. invalid geometries
2. disconnected endpoints
3. unintended gaps
4. unintended overlaps
5. duplicate reaches
6. self-loops
7. cyclic downstream relationships
8. confluence consistency
9. basin consistency
10. direction consistency

## Glacier/lake linkage

Preferred sequence:

`glacier → lake/source feature → validated outlet → stream reach → downstream network`

Spatial proximity alone is insufficient evidence for a definitive linkage. If linkage is inferred, the relationship must be labelled as inferred and retain its basis.

## Downstream traversal

For a validated source reach, HG-SCRIS can produce:

- connected downstream reaches
- tributary/confluence relationships
- cumulative network distance
- elevation change
- longitudinal gradient
- basin/sub-basin membership
- downstream settlements/infrastructure candidates

The traversal engine must reject cycles rather than silently returning an invalid path.

## Flow-routing rule

Network topology is a screening/connectivity representation. It does not calculate hydraulic depth, velocity, discharge, flood extent, debris-flow dynamics or arrival time unless a separate process model is explicitly run.

## Terrain integration

Where BUILD-03C terrain products are available, attach:

- upstream/downstream elevation
- longitudinal gradient
- local terrain slope
- relief
- valley profile references

Do not substitute valley slope for channel gradient.

## Exposure linkage

A settlement intersecting or connected to the network receives a connectivity relationship such as:

`SOURCE_CONNECTED → NETWORK_CONNECTED → SCENARIO_AFFECTED`

Only the final state requires a hazard/process scenario. Network connection alone must not be visualized as confirmed inundation.

## Output products

`hydrography_master`

`reach_graph`

`confluence_table`

`source_outlet_crosswalk`

`downstream_connectivity_table`

`hydrography_qa`

`hydrography_manifest`

## 2D visualization

Show separate layers for:

- source glacier/lake
- outlet
- river/stream network
- tributaries
- connected downstream reaches
- candidate exposed settlements

Use distinct symbology/status metadata for connectivity versus modelled hazard.

## 3D visualization

Terrain scenes may drape the network over the analytical terrain surface, but visualization elevation exaggeration must be recorded and must not alter analytical calculations.

## Animation readiness

The network graph supplies the spatial backbone for later temporal animation. Animation states will be generated by event/process models, not by assuming instantaneous travel along every connected reach.

## Acceptance gate

BUILD-03D is complete for a pilot only when:

- hydrography source is registered
- reach geometries pass QA
- direction is validated
- topology is valid
- source/outlet linkage is documented
- downstream traversal is reproducible
- connectivity results have lineage
- network connectivity is clearly separated from hazard extent
